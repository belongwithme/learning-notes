# 英语学习个性化分析与巩固训练 PRD 审核稿

版本：0.3  
日期：2026年10月10日  
状态：按用户反馈补充先学后练要求  
适用模块：学习档案中的英语学习模块

本需求让英语模块利用持续积累的学习记录，识别需要巩固的词汇和用法，为用户生成适合当前水平的材料与练习，再通过后续复测判断是否改善。用户每天应当能知道“现在该练什么、为什么练这些、练完之后还有什么不稳”，每周和每月能够据此调整学习重点。

第一版采用“Codex 辅助备课，网站学习与反馈”：用户在 Codex 中发起分析，Codex 通过固定工具读取学习数据、生成报告和练习，经校验保存后，用户在网站完成学习。网站记录作答和复测结果，供下一次 Codex 分析使用。网站第一版不直接调用模型 API，也不依赖 Codex 持续在线才能阅读已保存内容或答题。

本稿规定用户流程、业务规则和验收标准。文中的学习量、判断门槛及阶段划分均为本次建议方案，需审核后定稿。本文聚焦业务规则，工具使用与迁移验证见项目 README；报告生成与学习进度不得自动改写原始学习记录。

## 一 用户场景与问题

用户已经开始使用词库，一天可能学习一百多个词，并留下“忘了、模糊、记得”的记录。当前可以回看学习历史，但仍需要自己判断复习重点、寻找新例句和安排练习。

用户希望学习记录能够影响后续内容：今天没掌握的词得到针对性巩固，一周内反复出现的问题得到专题练习，一个月后能够判断哪些内容已经更稳定、哪些内容仍需调整学习方法。

### 一个完整的使用例子

以下为流程示例，不是用户实际学习数据或诊断结论。

1. 今天学习结束，用户在 Codex 中说：“分析我最近七天的学习记录，结合最近一个月的反复遗忘情况，生成一份包含详细讲解、语料精读和十分钟课后练习的 Java 英语课程，并保存到英语模块。”
2. 固定读取工具返回相关记录与统计，Codex 据此选择 `retain`、`release`、`allocate` 等重点词，列出“retain 在两个不同学习日被标为模糊”等依据，并区分自评事实与尚待验证的原因。
3. Codex 围绕 Java 资源管理生成逐词讲解、对比例句、带句子拆解的精读材料和少量课后题目，通过固定保存工具校验、保存并读回，返回网站中的对应内容入口。
4. 用户打开网站的“分析与巩固”，先学讲解，再读语料，确认学完后完成新语境题目。网站按预设答案记录词义题答对、搭配题答错等结果，无需在答题时调用 Codex。
5. 用户接受复测建议。下次请求 Codex 时，读取工具同时返回这些结果和待复测内容，Codex 为相应用法生成新的语境练习。
6. 周分析根据最新记录展示反复出错和已有改善证据的词条，并提供下一组专题练习。报告及题目保存在网站，不能只留在 Codex 聊天里。

## 二 目标与范围

### 产品目标

- 让已有学习记录产生可执行的下一步学习建议。
- 优先练习用户当前不稳定、反复遗忘且与学习目标相关的词汇和用法。
- 用新的上下文检查理解，逐步区分“看着熟悉”“能回忆”“能在句子中理解”和“能表达”。
- 通过跨日复测观察变化，避免把当天大量点击“记得”等同于长期掌握。
- 控制每日任务量，让用户能够持续完成。

### 第一版纳入范围

| 能力 | 用户可获得的结果 |
| --- | --- |
| Codex 发起分析与生成 | 通过对话指定时间范围、学习目标和学习量，按请求生成并保存内容 |
| 个人薄弱内容清单 | 词条、推荐原因、对应记录、当前证据与建议练法 |
| 每日学习与巩固 | 围绕少量重点词提供详细讲解、对比例句、语料精读和课后客观题，学习与练习均支持暂停与继续 |
| 练习反馈 | 答题结果、解释、是否使用提示，以及对应的词汇或用法 |
| 后续复测 | 用户接受的复测安排，以及在新语境下的复测结果 |
| 日周月分析 | 同一套学习事实按不同周期汇总，并给出相应的练习入口 |
| 历史结果回看 | 已生成的报告、练习及作答记录在不同设备上可继续访问 |

### 后续再考虑的范围

第一版不做发音评测、语音对话、自由作文自动评分、全网自动搜集语料、复杂等级认证或多用户教学管理。开放表达题可以在后续版本加入，届时需要独立定义 AI 评价、争议处理和评分可靠性。

第一版由用户在 Codex 中主动发起，网站只展示已保存的分析和练习，并承接作答与反馈。站内一键调用模型、定时生成、邮件或其他站外提醒属于后续可选能力，不在第一版范围内，不因本 PRD 自动创建任何定时任务。

## 三 现有基础与能力边界

现有模块包含 1000 个词汇、500 个表达和 20 个主题。已有记录模型保留每次自评的词条、结果与时间，并支持当前状态、优先级、计划日期、复习日期和笔记。

这些历史记录可以直接用于寻找反复遗忘和近期不稳定的内容，无须要求用户重新学习一遍。但已有记录没有实际答案、提示使用情况或错因，因此不能据此追溯生成“答题正确率”或断言用户存在某种语法缺陷。

当前“记得”会把词条状态设为“已掌握”。新分析需要明确提示：这是原有自评状态，不代表该词已通过跨日或语境练习验证。第一版保留原有状态和用户安排，新增分析证据，不自动批量改写历史状态。

未练过的词显示“尚未评估”；只有旧版状态而没有日期的词显示“历史日期未知”。记录少的主题不能直接判为薄弱主题。用户未作答也不计为答错。

### AI 接入方式与职责

第一版的 AI 分析和内容生成由 Codex 承担。网站无需另接一个模型服务，但需要新增个人报告、练习、作答和复测的数据保存与展示能力。以下读取与保存工具均为待建设能力，不代表目前已经接通。

| 环节 | 负责方 | 交付结果 |
| --- | --- | --- |
| 指定需求 | 用户在 Codex 发起 | 分析周期、学习目标、练习量及是否保存 |
| 读取与统计 | 固定读取工具 | 范围明确的学习事实、重点候选词、历史练习与复测结果 |
| 分析与编写 | Codex | 引用事实的报告、目标词、材料、题目、答案与解释 |
| 校验与保存 | 固定保存工具 | 已校验、可读回且可在网站打开的内容 |
| 作答与计分 | 网站 | 客观题结果、提示使用、用户反馈与复测完成记录 |
| 下一轮调整 | 用户再次请求 Codex | 基于实际新结果调整后的学习内容 |

数量、日期归属、重复判断和客观题计分由固定程序完成；AI 负责解释证据、编排重点和生成语料。分析效果不能依赖当前聊天是否保留全部上下文，每次应从保存的学习事实和历史内容重新取得必要依据。

### 固定读取与保存工具

第一版只需两个面向本学习模块的工具，不建设通用数据库操作后台：

- **读取学习上下文**：按请求周期和必要的历史观察范围，读取个人学习记录、相关词条、既有报告、练习结果和待复测安排，返回明确的数据截止时间及统计依据。该工具只读，不修改掌握状态或复习日期。
- **保存学习内容**：接收结构固定的报告与练习，校验词条存在、证据匹配、题目完整、答案格式及重复请求，保存后读回确认。只写入本次生成的学习内容，不通过任意 SQL 改写原始学习记录。

工具可以先由项目脚本实现，后续确有需要再封装为 MCP 工具。具体连接与认证方式属于技术方案；无论采用哪一种，读取范围、保存规则和结果验证保持一致。格式校验通过不代表教学内容一定正确，仍需保留题目纠错入口。

用户明确要求“生成并保存”时，校验通过即可在该次授权范围内保存，不额外增加逐条确认。只要求“分析”或“先看草稿”时，不自动发布到网站。保存范围无法确定时，由 Codex 在写入前澄清。

初次建设需要部署网站功能；之后每次生成的报告与练习都作为个人数据保存，不写入公开静态词库，不要求提交 Git 或重新部署网站。

## 四 页面与使用流程

### 分析与巩固入口

在英语模块增加“分析与巩固”入口，内含“今天、本周、本月、历史”四个视图。保留当前词库、今日学习和学习记录入口。

有已保存报告时，用户进入后先看到周期范围、数据截止时间、本期覆盖的词条数量，以及最需要处理的少量内容。页面同时提供“开始巩固”和“查看依据”，不要求用户读完长报告才能开始学习。没有对应报告时显示“尚未生成”，提供可复制到 Codex 的请求示例；第一版不展示会直接调用 AI 的“生成”按钮。

个人分析、练习及历史结果沿用现有个人记录的访问权限；公开词库仍可正常浏览。

### 每日流程

1. 用户在 Codex 发起今日分析，说明短练习或标准练习、需要补练或排除的词条；未说明的项目沿用已确认的偏好。没有当天记录时，可根据历史待复测内容生成建议；没有任何可用记录时提示先学习，不编造诊断。
2. Codex 读取上下文，生成带选词原因和预计学习量的报告与练习。用户可在对话中调整；已明确要求保存时，校验通过后直接保存。
3. 保存工具读回确认后，Codex 返回对应网站入口。只完成内容生成但保存失败时，明确告知“尚未保存到网站”，不得报告已可在线学习。
4. 用户在网站先阅读词汇与用法讲解，再完成语料精读，确认学完后进入新语境练习。课前学习允许自由阅读解释和译文，不记为答题提示；练习开始后回看教学材料或使用提示，未答题记为辅助作答，不计入“无提示首次作答正确率”。
5. 完成后网站按固定规则展示本次结果、需要继续练的内容和后续复测建议。用户确认后才加入复测安排。新的 AI 解释与新题目在下一次 Codex 请求时生成。
6. 中途退出后，可以从已保存的进度继续；没有确认保存的答案须有明确提示。网站回看和作答不要求 Codex 同时运行。

### 周月流程

用户在 Codex 中请求本周、本月或已结束历史周期的分析，保存后在网站对应视图查看重点问题和变化，进入已生成的专题练习。报告应允许从一个结论追溯到相关词条和学习记录。日、周、月指分析周期，不代表系统会自动在每天、每周或每月运行。

已保存报告不会随着新增记录悄悄变化。用户在 Codex 主动请求更新时，显示新的数据截止时间并保留先前版本；此前完成的练习和答案仍对应其原版本。网站发现该周期有晚于报告截止时间的新记录时提示“有新记录可用于更新”，不自动调用 Codex 或替换报告。

## 五 薄弱内容识别规则

### 证据分类

| 证据 | 可以支持的结论 | 不可以直接支持的结论 |
| --- | --- | --- |
| 忘了或模糊的自评 | 用户当时认为回忆不稳定，需要进一步练习 | 具体是语法、词义或技术概念出错 |
| 未提示的首次客观题答案 | 本次题目对应的词义、搭配或句子理解表现 | 已全面掌握该词所有含义 |
| 查看提示或答案后的作答 | 完成了一次辅助学习 | 独立掌握或无提示答对 |
| 跨日且换语境的复测 | 在该次新语境下仍能够理解目标用法 | 永久不会遗忘 |
| 用户主动选择的困难类型 | 用户自述卡在词义、搭配或句子理解 | AI 已验证的诊断 |

困难类型为可选反馈，不要求每学一个词都填写。AI 可以提出“可能原因”，但必须与已验证的题目结果分开展示。

### 第一版筛选与排序

以下门槛为审核建议，默认观察最近 30 个自然日。

- “反复不稳”：同一词在至少两个不同日期出现“忘了、模糊”或无提示首次客观题错误。
- “近期需巩固”：尚未达到反复不稳门槛，但最近一次有效自评为忘了或模糊，或最近一次无提示首次答题错误。
- “待复测”：用户接受的复测安排已到期，且尚无对应完成记录。
- “近期趋稳”：在最后一次不稳之后，至少两个不同日期的无提示首次复测正确，且其中一次距该次不稳至少 7 天。仅表示近期证据改善，不自动覆盖原有掌握状态。

同一个词只占一个每日推荐名额，可以同时展示多个推荐原因。待复测内容优先，其后为反复不稳、近期需巩固；同组优先考虑用户设置的优先级，再参考不稳日期数及距上次有效练习的时间。首次版本不展示未经验证的“掌握概率”或综合能力分数。

同一天反复作答不应被计算成多个独立学习日。达到“近期趋稳”的词移出反复不稳和近期需巩固清单，但仍可保留已确认的复测安排；再次出现不稳时重新纳入。不得让很久以前的错误一直占据每日推荐首位。

## 六 日周月分析内容与统计口径

### 分析内容

| 周期 | 必须回答的问题 | 应提供的下一步 |
| --- | --- | --- |
| 日分析 | 今天涉及哪些词，哪些仍不稳，哪些历史内容已到复测时间 | 一份可直接开始的巩固练习 |
| 周分析 | 哪些词在不同日期反复不稳，已尝试的哪些用法题错误较集中，哪些内容出现改善证据 | 一个优先专题和对应练习，可查看其选词依据 |
| 月分析 | 同一批词在跨日复测中的表现如何，哪些问题持续存在，当前学习量是否造成待复测积压 | 下月重点主题、复习与新词学习的调整建议 |

日报和周报不能仅通过扩大日期范围重复同一句总结。月分析不得依据词库学习数量推断 CEFR 等级、口语水平或工作能力。

### 日期与计数

- 全部周期按北京时间计算。自然日为当天 00:00 至次日 00:00；自然周从周一开始；自然月从每月一日开始，区间结束时刻不包含在内。
- 当前周期显示“截至某时刻”，与完整历史周期明确区分。未结束周期的变化比较采用上一周期相同已过时长；已结束周期与上一个完整周期比较。
- “自评词条数”按周期内有自评记录的不同词条计数；同一词多次自评只计一个词。“自评次数”另行计数，不混用。
- “练习词条数”按周期内提交答案关联的不同目标词计数；一题关联多个词时，各词分别进入词条覆盖数，但题目正确率仍只计算一题。
- “无提示首次作答正确率”仅统计每道有效客观题的第一次提交，且提交前未查看提示或答案。显示正确题数与总题数，重复重做不扩大分母。
- “跨日复测正确率”只统计标记为复测、在初始练习之后的另一自然日完成且未提前看答案的首次作答；与当日练习正确率分开展示。
- 数据读取失败显示“暂时无法读取”，不能显示为零；样本为零时显示“暂无可计算数据”。

### 变化与证据限制

不同周期题目和词条不同，整体正确率的升降只能描述本期表现，不能直接宣布能力提升。涉及“某批词改善”的结论，必须列明共同词条范围、复测间隔和样本量。

历史不足一周或一个月时，仍展示已有数据和覆盖日期；不补造完整周期。不足五个不同词条的主题不进入薄弱主题排名，但可以展示单词级证据。数据较少时优先给出试探性练习，不给确定性诊断。

## 七 个性化材料与练习

### 先学后练的完整学习单元（2026-10-10 用户补充）

生成结果必须包含足够学习的内容，不能只交付练习或在题目前放一小段英文。普通课程按“学习讲解 → 语料精读 → 课后练习”推进：

1. **学习讲解**：给出本课学习目标；对每个目标词解释当前含义、常见搭配与使用边界，配至少两个带译文和注释的完整例句，再通过一组易混表达对比解释差异。
2. **语料精读**：提供连贯的技术场景材料和全文译文，至少拆解两个关键句；按原句分块说明主干、修饰、条件或因果关系，解释如何理解，而非只给翻译；最后列出可迁移的学习要点。
3. **课后练习**：确认前两步已完成后开放题目；题目采用不同于教学例句的语境，考查迁移理解，保留既有题量、客观计分与纠错规则。

学习讲解与精读分别记录完成进度，刷新或换设备可继续；这些完成记录只代表用户确认已读，不代表答对或掌握，不扩大任何正确率分母。学习时长与练习时长分开显示，原先 5 分钟、10 至 15 分钟指练习部分。

练习开始后收起教学内容，回看讲解仍然允许，但对未答题标注辅助学习。跨日复测用于检查保留情况，保留先独立回忆、答后阅读讲解的顺序；提前学习材料则按辅助复测处理。旧版报告不补造学习内容或完成记录，新生成版本必须同时包含完整学习单元与练习，旧题和答案继续可回看。

### 内容范围

第一版默认服务于 Java 技术英语阅读：Java、JVM、Spring、SQL、缓存、消息、接口说明、故障排查及代码评审。Codex 应优先使用用户熟悉的技术背景，让学习负担集中在英语上；用户可以在生成请求中改为通用阅读场景。

每份练习保存目标词、目标含义或用法、难度选择和推荐原因。多义词优先练习词库中的目标含义，扩展其他含义时明确说明。

### 建议学习量

| 模式 | 目标词条 | 内容与题量 | 预计时间 |
| --- | --- | --- | --- |
| 短练习 | 全部未处理词条，不设词数上限 | 少量对比例句，约 80 至 120 个英文词的短文，3 道题 | 约 5 分钟 |
| 标准练习 | 全部未处理词条，不设词数上限 | 少量对比例句，约 150 至 220 个英文词的短文，5 道题 | 约 10 至 15 分钟 |

时间为供选择的估计，不作为用户表现评分。候选词不足时使用实际数量；候选过多时分批安排，不把一天所有不熟悉的词强行塞进一篇短文。每个选中的目标词至少出现在一个有意义的上下文和一道练习题中；一题可以考查多个目标词。

### 第一版题型

- 词义辨析：判断目标词在当前句子中的含义。
- 搭配或选词填空：从给定选项选择符合当前语境的用法。
- 句子与短文理解：判断条件、否定、范围、因果等表达的含义。

每道题必须提供题目、标准答案、解释和考查目标，且答案应能由题目语境确定。文本填空如允许多个正确形式，需事先明确可接受答案；存在歧义的题不得计入正确率。多词题答错但无法定位具体词时，只记录该题理解有误，再用单词级题目区分，不把涉及的全部词都判为未掌握。

对于搭配错误，后续优先提供对比例句；对于句子理解错误，优先提供更短句子与关系拆解；词义仍不稳时降低句子复杂度。调整依据来自实际题目结果或用户反馈，不只依赖所属主题。

### 难度和质量

首次使用默认采用短句和少量非目标生词，不把词库已有“技术扩展”等标签直接当成用户水平。用户可反馈“太难、合适、太简单”，影响下一份练习。

AI 教学例句和短文明示为生成内容，不包装成官方文档原文。第一版默认使用已有词库和生成材料；如人工加入真实摘录，应附来源并保留原意。词库中的主题参考链接不自动成为新生成段落的出处。

技术场景必须合理，不能为容纳词汇而编造 API 行为或错误技术结论。用户可标记题目有误；标记后该题进入待核对状态，暂不参与能力分析，原答案保留。修正前后的题目与结果可区分。

## 八 复测与学习安排

练习完成后，对答错、使用提示或仍自评模糊的目标词提出复测建议。第一版建议在下一自然日复测；通过后建议在该次成功后第 3 天、第 7 天再次复测。答错后回到较短间隔，具体日期由用户确认。

这些是初始复测建议，不宣称已经根据个人遗忘曲线优化。用户可以调整或跳过；跳过不等于遗忘。复测应更换句子或场景，保留考查的目标含义，避免只记住原题答案。

到期复测已有对应且未作答的新语境练习时，网站直接提供入口；尚未准备材料时，显示“待准备复测练习”，将其纳入下一次 Codex 读取范围。到期本身不触发 AI 生成，不把重做原题当成已完成新语境复测，也不把缺少材料计为用户答错。

自动建议与用户原有复习日期应清楚区分。已有手工安排时先展示冲突，由用户决定采用哪一个，不静默覆盖。重复确认同一建议不产生多份任务，多设备完成后以已确认保存的结果为准。

周月分析给出调整建议，不自动提高每日新词量。出现较多待复测内容时，优先建议先处理积压，并说明依据。

## 九 报告与练习保存规则

| 业务数据 | 需要保留的内容 | 用途 |
| --- | --- | --- |
| 原始学习记录 | 原词条、自评结果、时间和已有个人安排 | 兼容历史，追溯分析依据 |
| 周期分析 | 周期范围、截止时间、覆盖数、主要发现、引用证据、版本 | 重现当时的分析与建议 |
| 巩固练习 | 目标词及用法、材料、题目、答案与解释、生成时间、版本 | 继续学习和准确回看 |
| 作答记录 | 所属题目版本、首次答案、提示使用、结果、时间及重做记录 | 区分独立表现与辅助学习 |
| 复测安排 | 对应词和练习、建议日期、用户确认日期、完成情况 | 跟踪后续效果 |
| 用户反馈 | 困难类型、难度反馈、题目纠错标记 | 调整材料并处理争议 |
| 生成与保存凭据 | 本次请求标识、数据截止点、内容版本、保存结果 | 避免重复写入，确认聊天输出与网站内容一致 |

分析事实由可核对的记录统计得出，AI 负责解释、组织材料和提出建议，不自行生成学习数量或虚构历史。生成报告时固定其数据截止点；生成过程中新增的学习记录进入下一次更新。

同一周期、相同数据范围已有报告时优先打开已有结果。主动重新生成应保留版本并提示发生了更新；不得替换已答题目的内容。失败重试不得重复记录学习次数或创建多份相同复测安排。

报告与随附练习作为一份完整内容校验并保存，不能发布引用了缺失题目的报告。保存结果不确定时，先按同一请求标识查询是否已保存，再决定是否重试。成功凭据应包含可访问入口和内容版本；仅有聊天中的报告或工具返回成功文本，不足以认定网站已经可用。

第一版沿用现有词条标识，包括 W1000 等新增编号。上线验收必须覆盖新旧词条保存与读取，不把页面可搜索当作学习记录已保存。

## 十 异常与数据使用边界

- AI 生成失败或 Codex 当前不可用时，在对话中明确说明未完成，网站仍可使用原词库、已保存的报告和练习；不要求网站等待一个并不存在的后台生成任务。
- 页面刷新、网络中断或设备切换后，应能恢复已确认保存的报告、练习和答案。未确认保存的内容不能显示为完成。
- 模型输出缺少目标词、答案、解释或存在明显格式问题时，该练习不作为成功结果交付。
- 第一版 AI 分析仅使用本次所需的词汇、学习表现摘要和用户选择的目标。个人口令、数据库凭据不进入生成内容；私人笔记默认不提交给 AI。
- Codex 工作流本身会把选定的学习上下文交给 AI 处理。首次使用前说明所需数据范围；连接凭据由工具使用，不作为模型输入或网页内容。未运行该工作流时，仍可正常使用网站已有学习功能。
- 不因重新生成分析删除历史学习记录，也不把 AI 建议当作已完成的学习行为。

## 十一 业务验收标准

| 编号 | 验收场景 | 预期结果 |
| --- | --- | --- |
| A01 | 某日同一词有 5 次自评，另一词有 1 次自评 | 自评词条数为 2，自评次数为 6 |
| A02 | 同一词在两个不同日期标记模糊 | 可进入反复不稳清单，显示两次日期与结果，不直接判断为语法问题 |
| A03 | 用户当日重做同一道题多次 | 保留重做记录，首次作答统计不被重复扩大 |
| A04 | 用户先看提示再答对 | 标记为辅助作答，不计入无提示首次作答正确率 |
| A05 | 某词只有“已掌握”状态，没有学习日期 | 显示历史日期未知，不分配到某天，不生成虚构趋势 |
| A06 | 没有个人学习记录或读取失败 | 分别显示暂无记录或读取失败，不生成薄弱结论 |
| A07 | 一次生成包含 8 个目标词 | 每个词都有对应语境和考查题目，材料保留正确目标含义 |
| A08 | 用户完成练习后退出，再在另一设备进入 | 能读取同一练习版本、已保存答案和未完成部分 |
| A09 | 用户完成当天练习，接受后续复测 | 后续在新语境中考查，结果与当天练习分开统计 |
| A10 | 某词已有手工复习日期 | 建议不静默覆盖；用户确认后才改变有效安排 |
| A11 | 周期跨越北京时间午夜、周一或月初 | 每条有日期的记录正确归属，不重复或漏计边界记录 |
| A12 | 月度记录不足或两期考查内容不同 | 展示覆盖范围和样本量，不宣布确定的整体能力提升 |
| A13 | 重新生成已完成练习所在周期的报告 | 原题与作答仍能回看，新报告有独立截止时间和版本 |
| A14 | 生成超时、网络重试或重复确认安排 | 原功能可用，不增加虚假学习次数或重复安排 |
| A15 | 用户标记题目歧义或错误 | 该题暂不参与分析，原作答与标记保留 |
| A16 | 对旧词、新词及 W1000 完成学习和复测 | 保存后重新读取、跨设备查看的内容一致，不仅返回成功提示 |
| A17 | 生成周分析或月分析 | 主要结论可查看词条级依据，且有对应练习或可执行的安排建议 |
| A18 | 用户在 Codex 请求生成并保存 | 固定工具完成读取、校验、保存和读回，网站可打开相同版本，不需要重新部署 |
| A19 | 用户只请求分析或草稿 | 不新增网站报告或练习，不更改原学习记录 |
| A20 | 关闭 Codex 后在手机继续已保存练习 | 报告可读、题目可答、结果可保存，均不依赖实时 AI 连接 |
| A21 | 到期复测尚无对应的新语境材料 | 显示待准备状态，下一次读取可发现该安排，不假装生成成功或记为答错 |
| A22 | 用户完成新练习后再次请求 Codex 分析 | 读取到已保存的新答案和提示记录，推荐依据反映这些事实 |
| A23 | 同一生成结果保存时中断或重复重试 | 先查询既有结果，最终只保留一份该请求内容，报告和题目完整对应 |
| A24 | 本期尚无报告或已有报告后又产生新记录 | 分别显示尚未生成或可更新提示，保留准确截止时间，不自动发起模型调用 |
| A25 | 生成新的普通课程 | 每个目标词有讲解、用法、双语例句和易混对比，另有全文译文、句子分块与学习要点；缺少学习单元不允许发布 |
| A26 | 尚未完成讲解或精读就提交答案 | 不接受作答；完成两步学习后开放新语境练习，不把学习完成记为答对 |
| A27 | 学到精读阶段退出，换设备打开 | 恢复精读阶段，重复确认学习步骤不产生重复记录 |
| A28 | 练习开始后回看讲解，或复测前学习材料 | 允许继续学习，未答题标为辅助；保留此前已提交的独立答案 |
| A29 | 打开旧版报告 | 原报告与答案可继续使用，提示缺少完整讲解，不伪造已学状态 |

功能上线与实际学习改善分别验收。上线先验证记录准确、建议可解释、练习可完成和结果可回看；使用一段时间后再观察同一批词的跨日复测表现及用户反馈，不预先承诺提升百分比。

## 十二 审核重点与建议选择

本轮已确认的方向：第一版由用户在 Codex 发起分析和生成，网站承接已保存内容的学习与反馈。以下细节仍待审核，其余规则也可直接批注修改。

| 事项 | 建议选择 | 审核时需要决定的内容 |
| --- | --- | --- |
| 学习目标 | 先集中在 Java 技术英语阅读，保留通用场景选项 | 是否还要优先覆盖日常表达或技术写作 |
| 第一版范围 | 日周月分析一起提供，练习先做客观题 | 是否接受将自由表达与口语训练留到后续 |
| 每日学习量 | 提供约 5 分钟和约 10 至 15 分钟两档 | 哪一档作为默认，是否调整词量和题量 |
| 复测安排 | 系统建议，用户确认，保留手工日期 | 是否希望未来由系统自动安排 |
| 生成请求与保存 | 在 Codex 指定周期；明确要求保存即可校验后写入，仅分析时不发布 | 是否需要在网站提供常用请求的复制入口 |
| 数据范围 | Codex 只读取必要学习上下文，私人笔记默认不提交 | 是否有希望纳入分析的个人学习偏好或笔记范围 |

本稿采用的精简方案为两个固定读写工具、一个网站“分析与巩固”入口，以及可追溯的报告、练习和结果。日周月共享学习事实，不建立三套独立评分；第一版不增加站内模型服务、后台生成队列、MCP 服务、多模型协作或额外内容管理后台。

### 后续接入网站模型服务的条件

当用户确认需要直接在手机网页发起生成、无需打开 Codex 时，再评估由网站后台读取相同上下文、调用模型 API 并保存相同格式的内容。届时再确认模型、费用上限、数据处理范围与运行保障。现有报告、练习和作答记录应继续可用，不因更换生成方式重建学习历史。

### 2026-10-10 修订：全部未处理词条

用户要求每次处理今日最后自评仍为模糊或忘记、且尚未针对该次自评保存完整课程的全部词条。取消短练习 5 词、标准练习 8 词上限。词条较多时可以按主题分成多节，每节先完整学习后练习，但必须在同一次运行中全部保存；不能只列剩余清单后结束。已生成但未学完的课程不重复生成，也不阻止其他未覆盖词条备课。每次保存后重读数据库，以初始待处理集合全部被完整课程覆盖为完成条件；单词数较多的课程应如实标注学习时长，不承诺总共五分钟完成。
