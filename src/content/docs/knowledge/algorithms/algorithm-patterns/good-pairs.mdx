## 问题与样例

给定数组 `nums`，统计满足 **`i < j` 且 `nums[i] == nums[j]`** 的下标对数量。下标从 0 开始，同一个位置不能与自己配对。

贯穿本课的默认主样例是 **`[1, 2, 1, 1]`**。合法下标对为 **(0,2)、(0,3)、(2,3)**，所以答案为 **3**。即使数值都是 `(1,1)`，位置不同仍是不同数对；题目问的是数量，不是去重后的数值组合。

自定义输入只改变下方主演示及联动代码的状态解释；本节默认例题、错误实验和自测各自保留明确标出的样例。

## 必要概念：先读懂一轮

“枚举”就是按顺序逐个尝试。这里固定右端点 **j**，把它指向的数称为当前元素 **x**。在默认样例中，当 `j=3` 时，`x=1`。

**历史区**是已处理的左侧：下标 0、1、2，值为 `[1,2,1]`。**频次**就是出现次数，值 1 出现了 2 次。把值 1 当作**键**，用 `cnt[1]=2` 记下来，就能直接回答“左边有几个 1”。

<details>
  <summary>随用随查：查询、更新与枚举状态表</summary>
  <p>查询只读已有次数；没有这个键时读到 0，不把新键写入表。更新才改变次数，把当前元素也记进去。</p>
  <p>“枚举状态表”是维护已处理信息的问题模型。本课使用 HashMap 保存“值 → 次数”；小而连续的值域也可以使用频次数组。前后缀数组用于其他问题的左右信息预处理，本课不需要它们。</p>
</details>

## 暴力怎么做

固定右端点 j，从左到右，让 i 检查 `0…j-1` 的每个位置。默认样例依次检查：

`(0,1) 不同 → (0,2) 相同 → (1,2) 不同 → (0,3) 相同 → (1,3) 不同 → (2,3) 相同`。

6 次检查得到 3 对。它不会漏掉候选，但每来一个新的 j，都重新扫描左侧，重复做“哪些历史元素等于当前值”的寻找工作。下方切到“暴力枚举”，每一步都检查一对，而不只是展示成功配对。

## 为什么可以优化

默认样例处理最后一个 1 时，我们并不需要重新找出左边的每个 1，只需要知道**已经出现了 2 次**。每一个历史中的 1，都恰好与当前元素组成一个新数对，于是本轮直接增加 2。

把左侧的出现次数持续记下来，就能把内层逐个扫描替换成一次频次查询：**先查询 → 累加贡献 → 再把当前元素加入历史**。不是仅仅换成 Map，而是改变了重复寻找历史元素的方式。

正确性也由此得到：每个合法数对都有唯一的右端点。处理到它时，左端点已在历史中，因此不会漏算；只在这个右端点处理一次，因此不会重复。

| 0 | 1 | 0 | 0 | 0 | 1 → 1 |
| 1 | 2 | 0 | 0 | 0 | 1 → 1，2 → 1 |
| 2 | 1 | 1 | 1 | 1 | 1 → 2，2 → 1 |

## 复杂度：究竟省掉了什么

长度为 n 时，暴力检查 `0 + 1 + … + (n-1) = n(n-1)/2` 个候选数对，时间复杂度 **O(n²)**，除输出外额外空间 **O(1)**。

优化扫描做 **n 次频次查询、n 次频次更新**。HashMap 的查改平均为 O(1)，所以平均时间复杂度是 **O(n)**。保存 k 个不同值的次数需要 **O(k)** 额外空间，k ≤ n；最坏需要 O(n) 空间。这是用额外空间换掉重复扫描。

不同类型操作不能直接相加来宣称“快几倍”，也不能把动画播放时长当成 JVM 性能。页面为了讲解显示的配对列表和步骤快照，不属于 Java 算法的额外空间账本。

## 错误顺序实验：为什么会数到自己

本实验固定使用独立输入 **`[1]`**，不改变主输入和主演示位置。进入实验会暂停主演示，返回后也不自动播放。

正确顺序查询空历史，贡献为 0，再把 1 加入历史，结果 **0**。故意错误的顺序先更新再查询，读到 1 次，把 **(0,0)** 算进去，结果 **1**。违规的是 **`i < j`**，不是“数值不能相等”。
