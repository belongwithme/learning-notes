## 问题与默认样例

数组 **[4,5,0,−2,−3,1]，K=5**。统计区间和能被正整数 K 整除的**非空连续子数组**数量。负倍数和 0 都能整除，K 不能是 0。

合法闭区间为 **[0,5]、[1,1]、[1,2]、[1,4]、[2,2]、[2,4]、[3,4]**，共 **7**。其中 [3,4] 的和为 −5，[2,2] 的和为 0，不能只寻找正数和。

## 从区间差到同余分组

区间 [l,r] 的和是 P[r+1]−P[l]。设两个前缀分别是 aK+m、bK+m，差就是 (a−b)K，必然可整除。因此无需找完全相等的前缀，只要找**相同规范化余数**的历史前缀。

默认例子前缀为 **[0,4,9,9,7,4,5]**，规范化余数为 **[0,4,4,4,2,4,0]**。例如当前前缀 9 与历史前缀 4 的余数都是 4，差为 5，就找到一个区间。

表中的键从“完整前缀值”改成“余数”，值仍是历史出现次数。先放入空前缀余数 freq[0]=1；查完贡献后再记录当前余数，保证非空区间。

## 为什么 Java 需要归一化

Java 中 `-1 % 5 == -1`，但数学上的同余类还包括余数 4。前缀 −1 与前缀 4 的差是 5，应该能配对。

采用 **((cur % K)+K)%K**，将余数统一到 0…K−1。cur 用 long，运算完成后再转为 int。不要简单取绝对值：−1 应进余数 4 的桶，而不是余数 1。

## 为什么不漏不重，工作量如何变化

每个合法区间在处理其唯一右端点时，恰好与一个更早的同余前缀配对。每个历史位置记一次，所以相同余数有几次，就新增几段。

长度 n 的数组，暴力检查 n(n+1)/2 个候选，时间 O(n²)。优化扫描做 n 次匹配查询与 n 次频次记录，平均时间 **O(n)**；HashMap 最多保存 min(n+1,K) 个不同余数，额外空间 **O(min(n+1,K))**。如果改用长度 K 的频次数组，还需承担 O(K) 分配与初始化成本。

K=1 时所有区间都可整除，答案应为 n(n+1)/2。全零数组也一样。这是很好的边界核对方式。

## 错误实验：数学上同余，程序却分开了

独立样例 **[−1,5]，K=5**。前缀是 0、−1、4。正确做法把后两个前缀都放在余数 4 的桶，找到区间 [1,1]，结果 **1**。

故意不归一化时，−1 和 4 进入两个桶，错误结果 **0**。原数组中的负数仍合法，错误出在分组方式。

## Java：只改键的含义，不改计数语义

[查看联动 Java](#prefix-java)。与上一课相比，不再查询 cur−K，而是计算并查询当前余数 mod，最后记录同一个 mod。HashMap 的键可以用 Integer，累计前缀 cur 与答案 ans 仍保留 long。

暴力代码用 sum%K==0 判整除时无需把余数改成非负，因为只判断是否为 0；归一化针对的是优化方法中需要比较余数是否属于同一组。
