## 问题与样例

默认数组 **[1,2,1,2]，K=3**。统计和恰好为 K 的**非空连续子数组**数量，不是任意挑选元素。三个合法闭区间是 **[0,1]、[1,2]、[2,3]**，答案 **3**。区间可以重叠，位置不同分别计数。

“子数组”必须连续；原数组负数与 0 也合法。前缀 P[t] 仍表示前 t 项的和，原数组区间 [l,r] 的和为 P[r+1]−P[l]。

## 暴力方法：先把所有候选看全

固定左端点 l，从 r=l 开始向右延伸。每多一格就把 nums[r] 加到 sum，检查一次是否等于 K。换左端点时 sum 清零。

长度 4 的数组共有 4+3+2+1=10 个非空候选区间。这里用增量累加做到 O(n²)，不是每次重新求整段和的 O(n³) 写法。下方暴力演示也会显示所有不满足条件的候选。

## 优化推导：为什么查 cur−K

固定右端点 r，记 cur=P[r+1]。条件 P[r+1]−P[l]=K，移项得到 **P[l]=cur−K**。于是每来一个右端点，只需问：以前有几个前缀值等于 cur−K？

例如默认样例处理 i=3 时，cur=6，需要历史前缀 3；P[2]=3，对应左边界 l=2，因此新增区间 [2,3]。历史表的键是**前缀和**，不是原数组元素值。

`freq` 保存次数。多个相同值的历史前缀对应不同左边界，都应该计数，不能改用只保存存在与否的 Set。

## 空前缀与顺序

开始前放入 **freq[0]=1**，表示 P[0]=0 出现过一次。当 cur=K 时，目标前缀为 0，这样才能计入从原数组下标 0 开始的区间。

这不是预先把空子数组算作答案。查询时，只允许更早的前缀 P[0…r]；当前的 P[r+1] 尚未入表。因此区间至少包含一个元素。查询、累加完成后再记录当前前缀。

## 正确性与复杂度

每个合法区间有唯一的右端点，处理这个右端点时，它的左前缀已经在历史中，且满足 cur−K。频次精确表示可选左边界数量，因此不漏、不重复。

暴力检查 n(n+1)/2 个候选，时间 O(n²)、额外空间 O(1)。优化每个元素做一次前缀累加、一次匹配查询、一次频次记录，HashMap 平均查改 O(1)，总体平均 **O(n)**、额外空间 **O(n)**。更新语句内部读取已有次数，账本中的“匹配查询”仅指寻找 need 的那次查询。

图中为了教学保留的全部区间和快照，不是 Java 模板实际保存的数据。含负数时窗口扩大会使和变小，不能无条件使用滑动窗口替代。

## 两个错误实验：独立输入 [0]，K=0

正确做法得到 **1**，只有区间 [0,0]。漏掉空前缀会得到 **0**；提前记录当前前缀会得到 **2**，多算一个空区间 [1,0]，也就是左前缀与当前前缀是同一个位置。

<PrefixSumPlayer lesson="count" experiment />

顺序反转造成自匹配的直接反例是 **K=0**；不能声称任何非零 K 都必然多算一段。错误实验独立于主样例，进入时暂停主演示。

## Java：查询键与更新键不是一回事

[查看联动 Java](#prefix-java)。查询的是 **need=cur−K**，记录的是 **cur**，不能拿 hit+1 更新 freq[cur]。模板从原稿的一行查询累加中拆出 need 与 hit，便于对照步骤。

cur 与 ans 用 long：总和可能超出 int，10 万个零、K=0 时有 5,000,050,000 个非空区间。图中的原数组下标 i 是教学定位，增强 for 实际只声明 x。
